# Runply v0.3.0

Runply is an MIT-licensed application framework for agents, with a single CLI for local development and release execution.

## Included

- Application and tool contracts, validated model adapters, permission checks, in-process approvals, cancellation, SQLite run records, and artifact output.
- `runply new`, `install`, `build`, `test`, `generate tool`, `run`, `doctor`, and `inspect`.
- Official MCP SDK integration with stdio and Streamable HTTP, schema-preserving tool discovery, resources/prompts through the library API, and run-owned connection cleanup.
- `runply dev`: a loopback web inspector, file watching, and rebuilding without automatic run replay.
- Environment bindings and local `plan`, `deploy`, `status`, and `pause`. Existing runs retain their admitted release when a new release is activated.

## Install

Use Node.js 24 LTS and npm. Download `runply-0.3.0.tgz` and `runply-0.3.0.tgz.sha256` from this release. From their directory:

```sh
shasum -a 256 -c runply-0.3.0.tgz.sha256
npm install --global ./runply-0.3.0.tgz
runply new my-app
cd my-app
runply run
runply test
runply dev
```

The archive is npm-compatible but is not published to the npm registry. Dependencies are resolved during installation; it is not a vendored/offline dependency bundle.

## Validation and scope

The local validation record contains 351 passing tests on Node 22.23.2 and Node 24.22.1, packed-starter acceptance on both, and Chrome/Playwright desktop/mobile inspector acceptance. GitHub CI checks the source on Node 22/24 and Linux/macOS, plus the inspector on Linux.

The starter model is scripted; file reads, business tools, persistence, and report creation are real. Real model access requires registering an adapter and providing the appropriate endpoint/credentials. `add model` onboarding is not implemented. MCP server addresses or executables are supplied by the application owner.

Deployment currently targets a local Node process. It is not a cloud provisioner or sandbox. Token streaming, native model-schema output, durable continuation, an interactive approval inbox, OAuth onboarding, and a production HTTP/worker entry point remain outside this release.

Existing working-name data directories are not migrated or deleted. See the compatibility guide for explicit legacy-data paths and starter import changes.
